Ця картка допомагає швидко розділити симптоми на CPU, пам’ять, заповнення файлової системи або конкретний процес. Знімки стану краще робити до перезапуску сервісу.

## Знайти процеси з найбільшим CPU

> **Ризик: безпечно.** Команда лише читає таблицю процесів.

```bash
ps -eo pid,ppid,user,%cpu,%mem,etime,stat,cmd --sort=-%cpu | head -n 16
```

**Параметри:** `etime` — час роботи процесу, `stat` — його стан; сортування показує найактивніші процеси першими.

**Перевірка:** повторіть через 10–20 секунд — одноразовий пік не завжди означає проблему.

## Знайти процес за іменем і аргументами

> **Ризик: безпечно.** `pgrep -af` показує PID і повний command line.

```bash
pgrep -af '<pattern>'
```

**Параметри:** `<pattern>` — регулярний вираз; беріть у лапки, якщо він містить пробіли або shell-символи.

**Перевірка:** перевірте конкретний PID через `ps`.

```bash
ps -p <pid> -o pid,ppid,user,etime,stat,cmd
```

## Оцінити пам’ять без пастки free

> **Ризик: безпечно.** Для дефіциту пам’яті дивіться на `available`, а не лише на `free`.

```bash
free -h
```

**Параметри:** `-h` подає обсяг у зручних одиницях; cache Linux може бути звільнений, тому низьке `free` саме по собі нормальне.

**Перевірка:** перевірте, чи ядро не завершувало процеси через OOM.

```bash
journalctl -k -b --grep='Out of memory\|Killed process' --no-pager
```

## Побачити заповнені файлові системи

> **Ризик: безпечно.** `df` показує файлові системи, а не розмір окремих каталогів.

```bash
df -hT
```

**Параметри:** `-h` форматує розмір, `-T` додає тип файлової системи; звертайте увагу і на `%`, і на точку монтування.

**Перевірка:** якщо місце є, але запис не працює, перевірте inode.

```bash
df -ih
```

## Знайти найбільші каталоги

> **Ризик: безпечно, але може навантажити диск.** Запускайте на конкретній точці монтування в непіковий час.

```bash
sudo du -xhd1 <path> 2>/dev/null | sort -h
```

**Параметри:** `-x` не переходить на інші файлові системи, `-d1` обмежує глибину одним рівнем.

**Перевірка:** повторіть команду для найбільшого дочірнього каталогу, доки не знайдете джерело росту.

## Завершити процес коректним сигналом

> **Ризик: змінює систему.** Перевірте PID безпосередньо перед сигналом; повторне використання PID може влучити в інший процес.

```bash
kill -TERM <pid>
```

**Параметри:** `TERM` дозволяє процесу завершити cleanup. Не переходьте одразу до `KILL`, якщо немає аварійної потреби.

**Перевірка:** ненульовий код `ps` означає, що PID більше не існує.

```bash
! ps -p <pid> >/dev/null
```
